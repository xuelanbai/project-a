# 部署与复查

先阅读 [最终副本说明](../final/README.md)，再根据任务选择脚本，不要批量运行全部历史版本。

## 服务器已有部署

保留已有 `$PROJECT/config/params.yaml`、`samplesheet.csv`、`$APP/cutandtag_env.sh` 和 `$APP/conf/local_conda.config`。本归档没有替代这些实际文件的模板。备份原同名代码后，将最终副本的 config 文件配套部署到 `$PROJECT/config/`；环境预热 `.nf` 放到 `$APP/offline/`。

多数计算脚本带 Slurm 指令，使用 `sbatch` 在分配的计算资源内执行。`--check` 检查输入、路径或依赖存在性，没有证明分析任务已完成；详细行为看各脚本。需要创建的 logs 路径必须在 sbatch 前存在。主流程的本地执行器资源约束依赖实际 local_conda.config。

实际运行顺序：环境准备→主流程→pooled 轨道/共同峰→全基因 TSS 或候选筛查→精确定量；统计收集在目标输出生成后执行。已有输入可供后处理时无需重新从 FASTQ 开始。`-resume` 会复用 Nextflow 缓存，不能把 cached 任务记录为全部从头重跑。

## 版本核对

`final/VERSION.json` 给出最终版标识；`final/CODE_MANIFEST.json` 给出十个代码文件的历史原件位置和 SHA256；`final/SHA256SUMS.txt` 覆盖最终副本文件。历史归档自己的 manifest/checksum 仍留在原目录，校验时以其所在目录为基准。

计算节点无网络。环境安装/修复应提前在有网管理节点完成，计算节点复用共享安装；Nextflow offline 标志不能替代检查 pipeline/plugin/运行时资源是否已经就绪。
