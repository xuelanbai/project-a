# CUT&Tag：背景核查与后续阈值敏感性分析

## 第一轮：已有结果的信号重算

上传 `quantify_cuttag_signal_qc_v2.py` 和 `quantify_cuttag_signal_qc_v2.slurm` 到服务器项目的 `config` 目录，先 `bash quantify_cuttag_signal_qc_v2.slurm --check`，再 `sbatch quantify_cuttag_signal_qc_v2.slurm`。不用重新安装包，不联网，不修改主流程或旧结果，不生成新BAM或bigWig。

脚本通过已有deepTools环境的Python读取14条bigWig，使用原始区间长度加权积分，不用zoom近似。CPM在存在的contig内把未记录区间作为“现有BAM过滤后未观察到coverage”补零；不是证明没有生物学结合。缺失contig/显式NaN留作NA。MACS2 ppois缺失区间不补零，另报实际编码比例。ppois的区域均值、最大值或高分碱基比例都不是该区域的P/Q值。

输出包括：

- 12个候选基因的基因体、整段基因±2 kb、gene-level TSS±500 bp、±2 kb，以及有链方向的100 bp分箱。不是所有转录本TSS，也不是全基因组TSS enrichment score。
- rRNA/5S及rRNA邻域100 bp分箱；MT条目保留，但现有BAM可能已经过滤掉MT，零观察coverage不能当生物学阴性。当前注释的核rDNA表示有限；不包含核tRNA专项补注释。
- 两种Tag的MACS2/SEACR重复共同区域，以及119-Pol II共同区域的两个重复、匹配IgG和pooled ppois值。
- 119-Tag与Pol II的7个严格MACS2共占位候选，按照Tag共同区间定量，而非只对更宽的Pol II区间取均值。
- 每个位点最多20个比较区域：同染色体、同宽度，匹配TSS方向/距离、GC、ACGT比例、119-IgG及119-Pol II两个重复信号。候选比较区域也须与Pol II共同peak相交；不依据Tag信号选择，避免特意挑低Tag区域。

比较区域可能也有真实Tag结合，不是经实验证明的阴性区。只输出描述性分位与两种伪计数的log2(Tag/IgG)；由于7个位点本来按Tag peak选出，不能把排名或分位当正式P值/FDR。匹配不足会标记，不自动放宽匹配要求。

## 如何判断背景可能性

1. 两个Tag重复分别与同状态IgG比较：同时报告CPM差值、无伪计数倍数，以及伪计数0.01和0.1 CPM的log2比值。IgG为零的比值不设成无穷大；极低coverage、伪计数敏感的倍数不作为强证据。两个重复高于IgG是描述性筛查，不是显著性检验。
2. 与Pol II信号、TSS距离及序列组成相近的比较区域相比，检查候选处的Tag/IgG是否更突出。与全基因组随机区比较容易因启动子/开放染色质偏好而夸大证据，所以此轮使用同类Pol II区域。没有匹配区域时不能声称通过背景检验。
3. 保留137-Tag在同一位置的信号。119/137共享区域可能是真实共同通路，不能自动删去；119偏好应要求重复方向一致，并考虑两状态各自IgG。没有spike-in，跨状态比较只说明相对coverage。
4. 现有IP保留重复、IgG去重的处理可能影响对比。**本轮bigWig重算不检验这个问题**；对最终候选需做BAM级重复reads敏感性检查，采用明确、一致的计数/归一化方式，不因CUT&Tag局部重复较多就自动判PCR伪影。
5. IgG不能完全模拟抗Tag抗体非特异结合或游离Tn5在开放染色质的信号。每个状态只有一份IgG，不能估计对照的生物学变异。缺少ATAC/no-primary/KO对照，当前数据最多支持共占位候选；真正区分靶向结合和技术背景需要独立证据。共享基因/通路与蛋白物理互作也不是同一层面的结论。

## 第二轮：预先固定的MACS2敏感性方案（尚未执行）

|分析层级|q阈值|重复条件|IgG|用途|
|---|---:|---|---|---|
|当前主分析|0.01|两个重复均出现、正长度相交|同状态匹配IgG|主要结论|
|适度放宽|0.05|不变|不变|发现较弱但可重复候选|
|进一步探索|0.10|不变|不变|探索性候选，单独标注，不当主要结论|

保留同一BAM、BAMPE格式、同一gsize和duplicate策略，只改变q，便于判断变化来源。若保留重复策略不一致有明显影响，应另开一组对称duplicate处理的敏感性分析，不能把两种改变混为q阈值效应。

不能把q≤0.05的结果重新套用q≤0.01或“-log10(q)≥2”的二次过滤，否则放宽结果会被滤回原标准。可保留原p5q2统计作为对照，但不要用它定义放宽后的候选集。

`--broad`改变峰结构和连接方式，不是简单的“提高灵敏度”开关。只有轨道显示稳定的连续宽域时，才作为另一种峰形假设单独分析；TSS/局部结合仍先用narrow。BAMPE利用实际双端片段，不需要通过nomodel/shift/extsize的组合遍历来人为寻找结果。不得为增加peak数取消IgG或local-lambda背景。

评估每层：两个重复原始峰数、相互支持峰数、共同区间数/长度、峰宽、IgG-relative连续信号及新增位点分布。若有FRiP，应固定参考峰集再比较，不能用各自更宽/更多的峰集合计算FRiP后把其升高当作独立质量证据。当前Tag峰少，可能来自真实少量靶点、低信噪比、实验差异或分析限制；峰少本身不是阈值错误的证明。

单纯改变callpeak的q阈值主要改变peak判定，不应被用来“提高”已有pooled p-value bigWig的信号。在相同pileup、控制lambda和缩放下，ppois轨道不因选择更宽松的peak名单而变强。

## 依据

- [CUT&Tag原始方法论文](https://www.nature.com/articles/s41467-019-09982-5)，NPAT/CTCF实验讨论游离pA-Tn5在开放DNA上的信号及其对peak名单的影响。说明该背景机制确实可能存在，但不能证明本项目已发生。
- [deepTools/pyBigWig官方说明](https://github.com/deeptools/pyBigWig#compute-summary-information-on-a-range)，缺失碱基默认不计入均值分母；本脚本改为原始interval积分。
- [MACS维护者当前callpeak文档](https://macs3-project.github.io/MACS/docs/callpeak.html)，阐明q/p阈值、BAMPE、broad等概念。项目实际仍用MACS2 2.2.7.1，不升级软件；任何后续命令须先核对本机`macs2 callpeak --help`及输出xls中的真实参数，不能直接照搬MACS3新增选项。

本地已通过13项回归测试（补零、区间加权、缺失contig、TSS方向、正长度相交、伪计数、列对齐、匹配不使用Tag信号等）。服务器真实bigWig尚未重算；Slurm需要用户提交。脚本的`--check`只检查输入与依赖，不启动分析或写结果。
