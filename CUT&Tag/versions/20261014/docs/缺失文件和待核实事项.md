## 历史参数和解释需要核实的地方

- **BAMPE 与 shift/extsize**：历史调用同时携带 `-f BAMPE` 和 `--shift -75 --extsize 150 --nomodel`。文档与观测片段处理应核对；归档未自动改参数，也未把成功运行当作该组合符合文档的证明。
- **duplicate 处理**：target 来自 markdup BAM，IgG 来自 dedup BAM；上游过滤、duplicate flag 及不同工具解析行为需要核查。说明以输入 provenance 为准，不声称所有带标记片段必然进入了 MACS2 pileup。
- **gsize**：non-N 2,472,047,704 是这份 FASTA 的近似值。读长、MAPQ 和重复序列影响唯一可比对长度，不宜称为已精确测定的猪有效基因组大小。
- **归一化和跨状态**：CPM、软件内部 target/control 缩放、SEACR norm 与 spike-in 是不同概念。没有 spike-in，119/137 相对 coverage 不自动等于绝对结合量变化。
- **nolambda**：IgG 仍作为 `-c` 输入，但局部背景校正被取消。大量新增、重复共有峰仍可能由共同的染色质/测序偏好产生。q0.05 的值只在相应模型下解释。
- **pooled 与可重复**：pooled 新峰不要求两个重复各自显著；主要共同峰原则由单重复调用后交集实现。不能把 pooled 峰数写成两个重复共同峰数。
- **信号定量 v1**：multiBigwigSummary 区域均值可能受未编码碱基和默认统计方式影响。精确定量 v2 分开报告完整区间均值、编码碱基均值和 coverage fraction；历史初版保留用于审计。
- **TSS**：全基因 gene-boundary coverage profile 与候选基因 TSS 定量不是标准化 ATAC TSS enrichment score。TSS 脚本使用 `--missingDataAsZero`；精确定量脚本区分缺失情况，二者的缺失处理需结合用途说明。
- **FRiP**：归档没有新增统一 BAM 片段计数的 FRiP 脚本。上游源码中包含 peak QC 实现，但不能据此填写尚未从结果读到的数字。比较参数时应固定参考峰集/计数口径。
- **rDNA**：常规参考与注释可能缺失/折叠重复阵列，MAPQ 过滤也可能丢失多重比对片段；无注释重叠不能判定无结合。
- **生物学解释**：候选基因附近的 peak、Tag/Pol II 共占位和蛋白物理互作是不同证据。POLR1D 基因位点有峰也不是与 POLR1D 蛋白互作的证明。

## 运行和归档注意

自定义脚本原样保存，包含写死路径、固定软件环境 hash 和历史 job comparator。`--check` 是输入检查，并不等于算法验收或作业完成。并非每个脚本都支持 `--check`，以运行说明为准。

旧脚本会写入固定目录；不要因目录整理而直接批量执行全部 Slurm。新参数试验应保留独立目录、真实命令和输入 provenance。源码快照的 LICENSE 保留，不能将其称为服务器实际 pipeline 的完整验收记录。

`00_environment` 只预热 module 中的字面量 Conda specifications；并不保证所有运行时网络请求都已排除。当前自定义计算脚本使用已装工具和本地数据；nf-core 完整离线行为还受实际配置、插件和动态资源影响。

本次打包会核对源文件和归档 SHA256、ZIP 内容一致性，并生成校验报告。若做了本地语法或既有测试，会记录在 `validation.json`；这些检查不表示在真实计算节点重新跑过全流程。
