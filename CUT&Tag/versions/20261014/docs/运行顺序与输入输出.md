# 运行顺序与输入输出

## 环境和目录

服务器脚本使用下面的历史路径。包含 `&` 的路径必须加双引号。

```bash
PROJECT="$HOME/Projects/A/08.CUT&Tag/00.26.09/analysis_nfcore_cutandrun_3.2.2"
REF="$HOME/Projects/references/pig/Sscrofa11.1"
APP="$HOME/apps/cutandtag"
```

多数 Slurm 脚本写死了 `#SBATCH --output=/mnt/nas/swine/home/jxwu/.../logs/...`。修改 shell 中的 PROJECT 不会同步修改 SBATCH 日志路径。必须保证日志目录在提交前存在。代码分目录归档后，脚本内部仍使用旧输入/输出路径，目录分类不改变其查找规则。

以下为人工运行指南；本次整理没有执行这些服务器命令。现有结果可以直接供后处理使用，通常无需重跑主流程。先核实输入来源和已有输出，历史固定输出目录可能被重新写入；q0.05、broad/nolambda、精确定量按 job 建独立目录。

## 1. 在有网管理节点预热环境

将 `00_environment/prewarm_cutandtag_envs.nf` 放在 `$APP/offline/`。依赖已安装 Nextflow 23.10.1、本地 pipeline 与 mamba；使用 Nextflow 内部 hash，不能假设更换 Nextflow 版本后缓存命名仍相同。

```bash
source "$APP/cutandtag_env.sh"
cd "$APP/offline"
nextflow run prewarm_cutandtag_envs.nf \
  --pipeline_dir "$APP/pipelines/cutandrun-3.2.2" \
  --cache_dir "$APP/conda/envs"
```

默认 `install=false`，检查字面量 Conda specifications、conda-meta 和 SEACR 关键可执行文件。检查模式仍会产生 Nextflow 自身运行日志/元数据，且不检查所有传递依赖能否正常导入。

需要安装缺失环境时，使用同一命令加 `--install true`，在有网络的管理节点执行。若有 INCOMPLETE，脚本会停止安装；需先检查具体环境，再备份完整路径并修复。不要直接删除整个 envs 缓存。修复后再次运行检查。

## 2. 猪参考主流程 v2

上传主流程脚本到 `$PROJECT/config/` 后：

```bash
cd "$PROJECT/config"
bash run_cutandrun_pig_v2.slurm --check
# 输入和配置核对后，按需提交：
sbatch run_cutandrun_pig_v2.slurm
```

输入：完整 FASTA/FAI/GTF、现有 samplesheet/params、`local_conda.config`、环境初始化脚本、已存在 work/logs。脚本加载 `Java/17.0.15`，使用本地 Nextflow/pipeline，写入 `results_pig_v2/`。gsize 写入 `results_pig_v2/custom_metadata/macs_gsize_nonN.txt` 及 `logs/pig-v2-gsize-<jobid>.txt`。

Slurm 请求 32 CPU、192 GB；实际每个 Nextflow process 是否能在 allocation 内运行，依赖未归档的 local_conda.config。`--check` 只核对输入存在性和部分参数文本，不启动 pipeline，也不是所有参数解析的验证。

## 3. pooled 展示轨道、共同峰和 TSS

主流程完成后，先运行 `postprocess_cutandtag_pig_v2.slurm` 的 `--check`，再按需 sbatch。必须已有 gsize 文件、10 个 BAM，以及 8 个 MACS2 和 8 个 SEACR 峰文件。空峰文件允许，缺失文件报错。

主要输出：

- `custom_tracks/macs2_ppois/`：4 条 pooled ppois bigWig，以及每组 MACS2 peak/bedGraph 中间结果；文件名含 `rep1-rep2_pooled_vs_<state>_IgG_rep1`。
- `custom_tracks/reproducible_peaks_anyOverlap/`：两个 caller 的获支持原峰、共同 BED3 区间、`peak_counts.txt`。

该脚本以 `macs2 callpeak -t rep1.bam rep2.bam -c matched_IgG.bam -B` 合并输入，再经 `bdgcmp -m ppois`、排序、bedClip、bedGraphToBigWig 转换。现有非空 bigWig 会跳过，仅非空检查不能验证内容完整或生成参数相同。

随后可对 `run_cuttag_tss_v2.slurm` 执行 `--check` 和 sbatch。输入 10 条 CPM、4 条 pooled ppois、GTF/FAI；输出 `custom_tracks/TSS_allGenes/` 中的矩阵、profile 文本和 PDF。使用 gene-boundary TSS、链方向±3 kb、10 bp bin，保留零信号基因。这是 TSS coverage profile，没有输出标准化的 ATAC TSS enrichment score。

统计收集脚本 `collect_cuttag_v2_stats.slurm` 没有 `--check` 模式；直接 sbatch。它只扫描 published v2 结果的文本/峰文件，不读取 FASTQ/BAM/bigWig 的内容。输出 `logs/cuttag_v2_table_inputs.json.gz`，供本地表格代码使用。原 `logs/fragment_length.tsv` 仅作为旧来源收集，不能自动当成新版 BAM 的测量值。现有测试与该 Slurm 文件放在同一目录。

## 4. 严格峰注释与信号定量

`screen_cuttag_interaction_hypotheses.slurm` 输入严格 MACS2/SEACR 单重复峰、GTF、chrom sizes；输出 `hypothesis_screen_current_peaks/` 和同名 tar.gz。它生成后续共同峰、候选基因窗口及 rRNA/5S/tRNA 注释，因此 q0.05 和 broad/nolambda 依赖它。

初版 `quantify_cuttag_hypothesis_signals.slurm` 以 multiBigwigSummary 计算区域均值。存放在历史目录供溯源；区域均值解释以精确定量版本为准。

精确定量需要将 **Python 与 Slurm 两个文件同时部署** 到 `$PROJECT/config/`。Slurm wrapper 写死调用该 config 下的 Python，并不会自动调用 wrapper 同目录的 helper。提交前核对服务器 helper 与归档版本一致。

```bash
cd "$PROJECT/config"
bash quantify_cuttag_signal_qc_v2.slurm --check
sbatch quantify_cuttag_signal_qc_v2.slurm
```

输入：10 条 CPM、4 条 pooled ppois、筛查 BED、FASTA/FAI。依赖现有 deepTools 环境 Python、pyBigWig 和 pysam。输出 `hypothesis_signal_qc_v2/job-<jobid>/`、manifest、exact_signal TSV、候选 TSS/基因体/rRNA 分箱、匹配比较 JSON，以及作业 tar.gz。

CPM 在有效 contig 的未编码区域按未观察到 coverage 补零；缺失 contig/非有限值留 NA。ppois 未编码区域保持缺失。匹配比较区域不足会明确记录。它没有输出正式差异结合检验，也不验证 protein-protein physical interaction。

## 5. 参数敏感性

先部署 `06_sensitivity_q05/cuttag_macs2_q05_sensitivity.slurm` 到 config。用 `--check` 核对后 sbatch；只针对四个 Tag 重复，仍使用同状态 IgG。输出 `sensitivity_macs2_q05_Tag/job-<jobid>/` 和 tar.gz。没有重做 bigWig。

`07_sensitivity_broad_nolambda` 使用一个脚本、两个模式，必须指定模式参数：

```bash
cd "$PROJECT/config"
bash cuttag_macs2_broad_nolambda_sensitivity.slurm --check broad
bash cuttag_macs2_broad_nolambda_sensitivity.slurm --check nolambda
# 分别提交，需要哪个模式就提交哪个：
sbatch cuttag_macs2_broad_nolambda_sensitivity.slurm broad
sbatch cuttag_macs2_broad_nolambda_sensitivity.slurm nolambda
```

该脚本把 comparator 固定为 `sensitivity_macs2_q05_Tag/job-51897/`，并依赖严格 screen BED。改变 q05 作业号后需修改 `BASE_Q05`。broad 模式输出 broadPeak/gappedPeak，nolambda 模式输出 narrowPeak；两者都输出 shared_any、shared_reciprocal25、重叠统计、README、COMPLETED 和独立 tar.gz。它们没有生成新的 BAM 或 bigWig。

## 6. 本地统计表与 PPT

`08_local_tables` 的子目录按“模板→已填 v1→片段长度草稿/保留缓存版→v2 说明和填数”分类。Python 工具需要 openpyxl；MJS 表格工具需要 `@oai/artifact-tool`。多数输入和输出路径写死为原电脑磁盘路径，不能直接上传到 Linux 当计算脚本运行。

`update_cuttag_v2_workbook.mjs` 默认生成参数说明待填版，`--fill-v2` 从历史 JSON.GZ 填新版统计，`--inspect` 用于查看 workbook。运行前检查代码中的原工作簿、JSON.GZ 和输出路径。

`09_local_reports/20261013_v1` 是从统计/信号资料创建简洁汇报；`20261013_v2_focus` 的 prepare_data→inspect_source→build_focus 是区域/基因重点版。代码依赖当时的 artifact runtime、模板 PPT 和外部数据，归档只保存生成代码，未把它们改造成通用跨机器命令行程序。
